# Mobile node and connection interactions

Research date: 2026-09-21. Sources are first-party documentation and the Pointer Events specification. These are interaction patterns to adapt to Manatee's Mermaid document model, not a proposal to replace its renderer.

## Findings from comparable editors

- **Separate selection, movement and viewport gestures.** React Flow exposes independent settings for element selection, node dragging, pane panning, and pinch zoom. Its default viewport uses pointer drag to pan and pinch to zoom; it also has a configurable node drag threshold so a tap need not become a drag. [React Flow component API](https://reactflow.dev/api-reference/react-flow) · [Viewport behavior](https://reactflow.dev/learn/concepts/the-viewport)
- **Give thin connections a larger invisible hit area.** React Flow's `interactionWidth` renders an invisible path around each edge for clicking or tapping. Rete's selectable-connection example duplicates the visible SVG path with a transparent 15px stroke that receives pointer events and leaves the displayed stroke unchanged. [React Flow Edge API](https://reactflow.dev/api-reference/types/edge) · [Rete selectable connections](https://retejs.org/docs/guides/selectable/connections/)
- **Make touch targets and alternate gestures explicit.** React Flow's touch example enlarges connection handles and supports connecting by tapping two handles in succession. This is useful evidence for touch target size and tap sequences, though Manatee currently creates connections through Studio controls rather than canvas handles. [React Flow touch example](https://reactflow.dev/examples/interaction/touch-device)
- **Track input in screen and diagram coordinates.** tldraw tracks the pointer origin and current position in both coordinate spaces; drag thresholds use the screen-space origin, while movement is converted through the camera zoom. Its click detection distinguishes coarse touch input from fine pointers. Rete likewise warns that screen deltas diverge from area deltas when zoom is not one. [tldraw input handling](https://tldraw.dev/sdk-features/input-handling) · [tldraw click detection](https://tldraw.dev/sdk-features/click-detection) · [Rete selectable nodes](https://retejs.org/docs/guides/selectable/)
- **Decide who owns a touch before it starts.** The Pointer Events specification says `touch-action` declares whether the browser may pan or zoom; when the browser takes over, it suppresses the pointer stream with `pointercancel`. Changing `touch-action` during that gesture cannot reclaim it. [W3C Pointer Events, direct manipulation](https://www.w3.org/TR/pointerevents4/#the-touch-action-css-property) · [Pointer cancellation](https://www.w3.org/TR/pointerevents4/#the-pointercancel-event)

## Manatee implications

Before this change, [`MermaidSurface.tsx`](../../src/app/MermaidSurface.tsx) selected touch targets only after a short tap; touch movement was reserved for native scrolling. The surface's [`touch-action`](../../src/app.css) allowed two-axis pan and pinch. The SVG renderer drew each relationship as a thin path carrying `data-element-id` on its group, so its effective tap area was the visible path and label. See [`svg.ts`](../../src/mermaid/render/svg.ts). These observations explain why mobile selection of connections and direct node movement were hard, without implying a change to authored connection routing.

1. Add a transparent SVG hit path for each relationship, using the same geometry and ID, with a screen-space target wide enough to tap at fit zoom. Keep it out of export. Preserve visible selection styling and avoid letting the hit path cover adjacent nodes or connections indiscriminately. This adapts the React Flow and Rete techniques above.
2. Keep a tap for selecting nodes and relationships. Give node shapes and labels `touch-action: none` before pointer down so a finger can drag them, while leaving ordinary canvas space and connections scrollable and pinchable. Commit one undoable manual-position change on pointer up, and discard it on `pointercancel` or a second active pointer. The specification above makes a movement threshold alone insufficient while native panning is allowed on the same target. A dedicated drag handle remains an option if dense diagrams make node-origin scrolling difficult.
3. Measure tap/drag thresholds in CSS pixels and convert actual movement to diagram units through zoom, as the current mouse path already does. Selection should persist when moving between Canvas and Inspector. Relationships should select through the larger hit area, while a drag on a relationship should not silently issue a node-position command. [React Flow component API](https://reactflow.dev/api-reference/react-flow) · [tldraw input handling](https://tldraw.dev/sdk-features/input-handling)
4. Verify on touch-enabled Chromium and iPhone WebKit: tap node/connection at fit and zoomed views; scroll from blank space; drag a node without moving the viewport; cancel by a second finger and by `pointercancel`; pinch zoom; select dense or crossing connections; undo/reopen a manual position; and confirm SVG/PNG exports contain no invisible interaction path. These checks follow Manatee's existing [mobile verification scope](../ux-review.md) and cover the browser behavior described by [Pointer Events](https://www.w3.org/TR/pointerevents4/#the-touch-action-css-property).
